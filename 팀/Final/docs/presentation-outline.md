# 최종 발표 구성안

## 1. 문제 (20초)
"취업 준비자가 기업의 AI 전략을 제대로 확인하려면 수백 쪽의 사업보고서를 여러 연도에 걸쳐 직접 비교해야 합니다."

화면:
- 2024 약속
- 2025/2026 실행 근거
- 사람이 직접 연결해야 하는 문제

## 2. 해결 (20초)
AI Promise는 공시에서:
1. AI 약속을 찾고
2. 후속 공시에서 관련 근거를 검색하고
3. 4개 판정으로 정리하고
4. 원문 링크와 면접 카드로 연결합니다.

## 3. AI Native 구조 (35초)
강조 순서:
- RAG: 후속 정기공시 검색
- 자동화 워크플로우: OpenDART 자동 수집 → Collect → Extract → Retrieve → Judge → Verify → Card
- Agent-style retry: AI 판정이 '공시에서 확인 불가'이면 새 검색어로 다시 찾습니다(처음 검색 포함 최대 3번, 쓸 새 검색어가 없으면 그 전에 멈춤)
- 원문 존재 확인(Citation verification): AI가 고른 근거가 실제 원문에 글자 그대로 있는지 코드로 확인. 판정이 맞다는 뜻은 아니어서, 사람이 원문을 읽고 판정을 확인한 "사람 원문 검토"(검증 시연 2곳)와 화면에서 따로 표시

주의:
'완전 자율 Agent'라고 과장하지 않고 구현된 범위만 설명합니다.

## 4. 실제 데모 (70초)
추천 데모:
- 검증 시연 기업 1곳 선택 (삼성전자)
- 약속 목록
- 약속 상세
- 원문 근거
- 판정 이유
- 면접 카드
- 내 경험 연결 (v2): 지원 직무를 고르고 가상 이력서를 넣어 직접 연결, 간접 연결(한계 문장), 내 이력서에 없는 부분과 면접 전에 준비할 것을 보여 주기 (분석에 20~30초 걸리므로 녹화본이나 미리 받은 결과 화면을 준비)
- (시간이 되면) 확장 분석 기업 1곳(AI 엔진 결과)을 열어 같은 형식과 원문 링크를 보여 주기

핵심 멘트:
"AI가 결론만 주는 것이 아니라 원문까지 되돌아갈 수 있게 설계했습니다."

데모 시작에 한 문장으로 밝힙니다: 검증 시연 기업 2곳은 사람이 원문을 읽고 판정한 데이터(PR #19, 사람 원문 검토 완료)이고, 확장 분석 기업 3곳은 사람 검토 전 AI 엔진 결과입니다 (`docs/judge-qa.md` Q6).

## 5. 검증 (25초)
실제 수치만 사용:
- SK하이닉스 시범 평가: 약속 3개 × 같은 엔진 3번, 사람 정답과 1회차 2/3, 2회차 3/3, 3회차 2/3. 독립 표본 9개가 아니라 정확도로 주장하지 않음 (`eval/results/skhynix_runs.md`)
- 실패 분석 슬라이드 1장: QLC 61TB는 세 번 모두 같은 근거를 찾았지만(검색 안정) 근거 확인과 일부 확인 사이에서 판정이 흔들림(판정 경계). 후속: 경계 규칙, 2단계 확인, 판정 갈림 표시
- 원문 존재 확인: 확장 분석 3곳의 약속·근거 36문장이 모두 DART 원문에 있음 (`docs/company-expansion-plan.md`)
- 실제 사용자 설문 14명: 고치기 전 화면 12명(10/19 23:15~23:58), 고친 화면 배포 뒤 2명(10/20 02:17, 02:25)
- 고치기 전 12명: 이해도 4.50/5, 신뢰도 4.58/5, 활용 의향 4.67/5, 핵심 과업 완료 8/12
- 고친 뒤 2명은 인원이 적어 비교 수치로 쓰지 않고 의견만 소개

수치가 없으면 절대 만들어 넣지 않습니다.

## 6. 사용자 피드백 반영 (20초)
"사용자들이 화면을 이해하기 어려워해(개선 의견 6건 중 4건) 첫 화면 사용 순서 안내, 약속·근거 형광 표시, 용어 풀이, '실행 시기 전' 표시, 이력서 분석 진행 표시를 개선했고, 이 변경은 PR #41로 남겼습니다. 고친 화면을 배포한 뒤에는 글자가 많아 핵심이 안 보인다는 의견(2명)과 이력서 연결이 직무보다 제품 약속에 끌려간다는 의견(1명)을 받아, 설명을 접어 두고 지원 직무 기준으로 연결하도록 한 번 더 고쳤습니다(10/20 v2)."

화면: `docs/images/feedback/`의 고치기 전·후 이미지 5장(FB-01~FB-05)과 결과 차트(`user-test-results.png`). 발표 슬라이드 크기(1920x1080)로 만들어 그대로 넣을 수 있습니다.

## 7. 차별점과 한계 (20초)
차별점:
- 단순 공시 요약이 아니라 '약속 ↔ 후속 근거' 연결
- 원문 존재 확인(citation verification)과 사람 원문 검토를 나눠 표시
- 취업 면접 사용 맥락, 지원 직무 기준의 보수적인 경험 연결

| 비교 | 자료 없이 일반 생성형 AI에 묻기 | AI Promise |
|---|---|---|
| 근거 | 답의 출처를 사용자가 따로 찾아야 함 | DART 원문 문장을 그대로 인용하고 원문 링크 제공, 인용은 코드가 원문 존재 확인 |
| 시간축 | 한 시점의 설명이나 요약 | 2024 약속 ↔ 2025·2026 후속 공시 근거 연결 |
| 표현 | 단정 표현이 나올 수 있음 | 판정 4가지, '공시에서 확인 불가'는 미이행이라는 뜻이 아님 |
| 이력서 연결 | 경험과 회사 키워드를 바로 잇기 쉬움 | 경험 → 지원 직무 역량 → 회사 AI 약속, 직접/간접 구분, 억지 연결 안 함 |
| 검증 기록 | 각자 확인 | SK하이닉스 사람 정답과 3회 반복 비교(1회차 2/3, 2회차 3/3, 3회차 2/3), 사용자 설문 14명 |

한계:
- 공시에 나오지 않은 실행은 판단할 수 없음
- '공시에서 확인 불가'는 미이행을 뜻하지 않음
- 확장 분석 기업 3곳은 사람 검토 전 AI 엔진 결과라 검증 시연 기업과 검증 수준이 다름

## 마지막 한 문장
"AI Promise는 기업을 대신 평가하는 서비스가 아니라, 사람이 공식 공시를 더 빠르고 검증 가능하게 읽도록 돕는 AI 조사 도구입니다."
