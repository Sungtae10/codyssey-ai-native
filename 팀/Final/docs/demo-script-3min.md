# 3분 시연 대본

> 실제 사용자 수와 점수는 설문 완료 후 [입력]을 교체합니다.
> 화면 데이터가 아직 검증용 시연 데이터(PR #19)이면 0:40 부분의 괄호 문장을 꼭 넣습니다. 10/19 기준 삼성전자 화면에는 '공시에서 확인 불가' 판정이 없어서, 판정 종류를 하나씩 말하지 않습니다.

## 0:00–0:20 문제
“취업을 준비하면서 기업의 AI 전략을 제대로 보려면 사업보고서를 여러 연도에 걸쳐 직접 비교해야 합니다. 문제는 한 보고서가 수백 쪽이고, 과거에 무엇을 계획했는지와 이후 실제 공시 근거를 연결하는 데 시간이 많이 든다는 점입니다.”

## 0:20–0:40 서비스
“AI Promise는 이 과정을 자동화합니다. 과거 사업보고서에서 AI 관련 약속을 찾고, 후속 공시에서 실행 근거를 검색한 뒤 원문과 함께 판정해 보여줍니다.”

## 0:40–1:45 실제 화면
“먼저 기업을 선택합니다. 삼성전자를 보겠습니다.”

(검증용 시연 데이터일 때) “지금 보시는 화면은 실제 공시를 사람이 원문과 대조한 검증용 데이터이고, 엔진도 같은 형식으로 결과를 만듭니다.”

“약속 목록에는 약속마다 판정이 붙어 있고, 판정별 개수만 보여 줍니다. 점수나 순위는 만들지 않았습니다.”

“약속 하나를 누르면 2024년에 회사가 적은 원래 문장과 이후 사업보고서 또는 반기보고서의 근거 문장을 나란히 볼 수 있습니다.”

“여기서 중요한 건 AI가 결론만 주는 것이 아니라 사용자가 DART 원문으로 다시 확인할 수 있다는 점입니다.”

“마지막 면접 카드에서는 확인된 근거를 핵심 이슈, 답변 소재, 역질문으로 바꿔 줍니다. 완성 답변이 아니라 공시 근거가 붙은 소재로만 제공합니다.”

## 1:45–2:15 AI Native 구조
“기술적으로는 RAG를 통해 후속 공시에서 관련 문단을 검색하고, 근거가 약하면 검색어를 제한적으로 바꿔 재검색합니다. 이후 LLM이 판정하고, 선택된 인용문이 실제 수집 원문에 존재하는지 citation verification으로 다시 검사합니다.”

“전체 흐름은 Collect, Extract, Retrieve, Judge, Verify, Interview Card, Export의 Python 자동화 워크플로우로 연결했습니다.”

“반복적으로 나온 피드백은 [입력]이었고, 이를 [입력]으로 수정해 GitHub [입력]에 반영했습니다.”

## 2:40–3:00 한계와 결론
“AI Promise는 기업이 실제로 약속을 지켰는지를 단정하지 않습니다. 공시에 없는 실행은 알 수 없기 때문에 근거를 못 찾은 경우 ‘공시에서 확인 불가’라고 표시합니다.”

“저희가 만든 것은 기업을 대신 평가하는 AI가 아니라, 사람이 공식 공시를 더 빠르고 검증 가능하게 읽도록 돕는 AI 조사 도구입니다.”
