# 3분 시연 대본

> 실제 사용자 수와 점수는 설문 완료 후 [입력]을 교체합니다.
> 삼성전자 화면은 사람이 원문을 대조한 검증용 시연 데이터(PR #19)라서 0:40 부분의 괄호 문장을 꼭 넣습니다. 10/19 기준 삼성전자 화면에는 '공시에서 확인 불가' 판정이 없어서, 판정 종류를 하나씩 말하지 않습니다.

## 0:00–0:20 문제
“취업을 준비하면서 기업의 AI 전략을 제대로 보려면 사업보고서를 여러 연도에 걸쳐 직접 비교해야 합니다. 문제는 한 보고서가 수백 쪽이고, 과거에 무엇을 계획했는지와 이후 실제 공시 근거를 연결하는 데 시간이 많이 든다는 점입니다.”

## 0:20–0:40 서비스
“AI Promise는 이 과정을 자동화합니다. 과거 사업보고서에서 AI 관련 약속을 찾고, 후속 공시에서 실행 근거를 검색한 뒤 원문과 함께 판정해 보여줍니다.”

## 0:40–1:45 실제 화면
“첫 화면에서 회사를 검색합니다. 분석을 마친 회사는 바로 결과가 열리고, 아직 분석하지 않은 상장 기업은 '아직 분석 전'으로 그대로 보여 줍니다. 삼성전자를 보겠습니다.”

(꼭 넣기) “지금 보시는 판정은 사람이 공시 원문을 직접 읽고 대조한 검증용 데이터입니다. 첫 화면의 확장 분석 기업 3곳은 AI 엔진이 공시를 자동으로 받아 같은 4단계 형식으로 만든 결과입니다.”

“약속 목록에는 약속마다 판정이 붙어 있고, 판정별 개수만 보여 줍니다. 점수나 순위는 만들지 않았습니다.”

“약속 하나를 누르면 약속, 후속 공시의 근거, 판정이 시간 순서로 이어지고, 아래 확인 4단계에서 단계마다 누가 했는지와 원문 일치 여부를 보여 줍니다.”

“여기서 중요한 건 AI가 결론만 주는 것이 아니라 사용자가 DART 원문으로 다시 확인할 수 있다는 점입니다.”

“마지막 면접 카드는 공시에서 확인할 핵심 이슈, 면접에서 활용할 소재, 회사에 물어볼 역질문 세 묶음입니다. 완성 답변이 아니라 공시 근거가 붙은 소재로만 제공합니다.”

(시간이 되면) “면접 카드 아래에서 이력서 내용을 넣으면, 이 회사 AI 약속과 이어지는 제 경험과 보완할 점을 찾아 줍니다. 이력서 인용은 제가 넣은 글에 그대로 있는 구절만 보여 주고, 이력서는 저장하지 않습니다.”

## 1:45–2:15 AI Native 구조
“기술적으로는 RAG로 후속 공시에서 관련 문단을 검색하고, LLM이 그 문단만 근거로 판정합니다. 판정이 '공시에서 확인 불가'이면 새 검색어로 다시 찾고(처음 포함 최대 3번), 마지막으로 선택된 인용문이 실제 수집 원문에 있는지 citation verification으로 다시 검사합니다.”

“전체 흐름은 OpenDART 자동 수집부터 Collect, Extract, Retrieve, Judge, Verify, Interview Card, Export까지 Python 자동화 워크플로우로 연결했습니다.”

## 2:15–2:40 사용자 테스트
“실제 사용자 [입력]명을 대상으로 테스트했고, 이해도 평균 [입력]/5, 신뢰도 [입력]/5, 면접 활용 의향 [입력]/5를 기록했습니다.”

“반복적으로 나온 피드백은 [입력]이었고, 이를 [입력]으로 수정해 GitHub [입력]에 반영했습니다.”

## 2:40–3:00 한계와 결론
“AI Promise는 기업이 실제로 약속을 지켰는지를 단정하지 않습니다. 공시에 없는 실행은 알 수 없기 때문에 근거를 못 찾은 경우 ‘공시에서 확인 불가’라고 표시합니다.”

“저희가 만든 것은 기업을 대신 평가하는 AI가 아니라, 사람이 공식 공시를 더 빠르고 검증 가능하게 읽도록 돕는 AI 조사 도구입니다.”
