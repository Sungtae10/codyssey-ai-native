# AI 판정 설명·근거 점검 (10/20)

화면에 나온 판정 15개(구체적 약속)를 대상으로, 사용자가 판정 이유를 확인할 수 있는지와 근거가 DART 원문으로 이어지는지를 점검했습니다. 판정이 맞는지(정확도)를 사람이 다시 매긴 기록이 아닙니다. 사람이 원문을 읽고 판정을 확인한 것은 삼성전자·SK하이닉스 6개(사람 원문 검토 완료)이고, 카카오·현대자동차·신한지주 9개는 AI 엔진 결과(사람 원문 검토 전)입니다. 이 점검은 Claude가 결과 파일과 엔진 기록을 읽어 한 AI 보조 점검입니다.

## 1. 화면에서 판정 이유를 확인하는 곳

약속 상세 화면 하나가 "검증 카드" 역할을 합니다. 새 기능을 만들지 않고, 이미 있는 칸이 아래 질문에 모두 답하는지 확인했습니다.

| 확인할 것 | 화면 위치 | 데이터 |
| --- | --- | --- |
| 기업이 무엇을 약속했나 | 01 "약속 · 2024 사업보고서": 원문 문장 그대로, 보고서·장·전자공시 쪽 | `promises[].sentence`, `source` |
| 무엇이 실행 근거로 확인됐나 | 02 "근거 · 후속 공시": 근거 문장, "원문 존재 확인" 배지, 원문 보기 링크, 약속과 같은 말 형광 표시 | `evidence[]` |
| 왜 이 판정인가 | 03 "판정": 판정 이름, 판정 뜻 한 줄, 판정 이유(확인된 부분과 확인되지 않은 부분) | `verdict`, `reason` |
| 아직 실행 시기가 아닌가 | 약속한 시기가 근거를 찾은 범위(2026 반기보고서, 6월 말)보다 뒤면 "실행 시기 전" 안내 | 약속 문장의 시기 표현 (FB-03) |
| 원문으로 직접 확인 | 화면 아래 DART 원문 버튼 2개(약속 보고서, 근거 보고서) | `source.url` |
| 누가 확인했나 | 확인 4단계(처음에 접힘): 원문 존재 확인 N/M, 사람 원문 검토 완료/전 | 기업의 `data_mode` |

## 5. 다시 해 보는 방법

1. `app/data/results.json`에서 `type`이 `specific`인 약속의 `verdict`, `reason`, `evidence[].citation_verified`, `evidence[].source.url`, `source.url`을 셉니다.
2. AI 엔진 기업은 `data/work/<기업>/llm_log.jsonl`에서 `task`가 `judge`인 줄을 찾아, 판정 모델이 받은 후보 문장을 읽습니다. 후보 문장 번호는 `data/work/<기업>/judged.json`의 `search_log`에 있습니다.
3. 화면은 운영 사이트의 약속 상세(`#/c/<기업>/p/<약속 번호>`)에서 01 약속, 02 근거, 03 판정, 원문 버튼, 접힌 확인 4단계를 차례로 엽니다.
