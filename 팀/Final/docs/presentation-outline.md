# 최종 발표 구성안

## 1. 문제 (20초)
"취업 준비자가 기업의 AI 전략을 제대로 확인하려면 수백 쪽의 사업보고서를 여러 연도에 걸쳐 직접 비교해야 합니다."

화면:
- 2024 약속
- 2025/2026 실행 근거
- 사람이 직접 연결해야 하는 문제

## 2. 해결 (20초)
AI Promise는 공시에서:
1. AI 약속을 찾고
2. 후속 공시에서 관련 근거를 검색하고
3. 4개 판정으로 정리하고
4. 원문 링크와 면접 카드로 연결합니다.

## 3. AI Native 구조 (35초)
강조 순서:
- RAG: 후속 정기공시 검색
- 자동화 워크플로우: Collect → Extract → Retrieve → Judge → Verify → Card
- Agent-style retry: 근거가 약하면 제한된 횟수로 검색어를 바꿔 재검색
- Citation verification: AI가 고른 근거가 실제 원문에 존재하는지 코드로 확인

주의:
'완전 자율 Agent'라고 과장하지 않고 구현된 범위만 설명합니다.

## 4. 실제 데모 (70초)
추천 데모:
- Core 기업 1곳 선택
- 약속 목록
- 약속 상세
- 원문 근거
- 판정 이유
- 면접 카드

핵심 멘트:
"AI가 결론만 주는 것이 아니라 원문까지 되돌아갈 수 있게 설계했습니다."

화면 데이터가 검증용 시연 데이터(PR #19)이면 데모 시작에 한 문장으로 밝힙니다 (`docs/judge-qa.md` Q6).

## 5. 검증 (25초)
실제 수치만 사용:
- Human review / blind evaluation 결과
- citation verification
- 실제 사용자 __명
- 이해도 __/5
- 신뢰도 __/5
- 활용 의향 __/5

수치가 없으면 절대 만들어 넣지 않습니다.

## 6. 사용자 피드백 반영 (20초)
"사용자들이 __를 어려워해 __를 개선했고, 이 변경은 PR/commit __로 남겼습니다."

## 7. 차별점과 한계 (20초)
차별점:
- 단순 공시 요약이 아니라 '약속 ↔ 후속 근거' 연결
- 원문 citation verification
- 취업 면접 사용 맥락

한계:
- 공시에 나오지 않은 실행은 판단할 수 없음
- '공시에서 확인 불가'는 미이행을 뜻하지 않음
- Demo 기업은 Core와 검증 수준이 다름

## 마지막 한 문장
"AI Promise는 기업을 대신 평가하는 서비스가 아니라, 사람이 공식 공시를 더 빠르고 검증 가능하게 읽도록 돕는 AI 조사 도구입니다."
