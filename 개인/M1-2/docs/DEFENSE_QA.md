# 평가 대비 노트: 과제 목표 6개를 내 말로 설명하기

동료 평가에서 "AI가 그렇게 만들었다"는 답은 통하지 않습니다. 아래는 각 목표를 **한 문장 요약 → 쉬운 설명 → 코드 위치** 순서로 정리했습니다.
소리 내어 한 번씩 읽어 보고, 코드 위치를 직접 열어 확인해 두세요.

---

## 1. 시계열 분석 → 요약 → 서비스 활용 흐름

**한 문장**: CSV 251개를 분석해 "기간, 개수, 평균·최고·최저, 최근 추세, 월별"로 줄인 요약을 만들고, 그 요약을 화면 요약판과 AI 프롬프트에 같이 씁니다.

- 데이터 준비: `scripts/prepare_data.py`가 FRED H.10 환율에서 2025-10-16 ~ 2026-10-16 한국 원화 값만 고르고, 값이 없는 고시 휴일 11일은 뺍니다 (가짜 값을 채우면 변동성이 작게 나오므로).
- 분석: `app/services/analysis.py`의 `compute_summary`. 추세는 "최근 20개 평균 vs 직전 20개 평균"을 비교하고 ±0.5%를 넘으면 상승·하락으로 봅니다.
- 0.5%의 근거: 하루 평균 변동폭이 6.86원(평균의 약 0.47%)이라, 한 달 평균이 하루치만큼도 안 움직이면 방향이 없다고 판단했습니다.
- 활용: 같은 함수가 `GET /api/data/summary`, 화면 요약판, `/api/chat`의 시스템 프롬프트에 쓰입니다. 그래서 세 곳의 숫자가 항상 같습니다.

**예상 질문**: 왜 합계(total)는 없나요?
→ 환율은 더해서 의미가 있는 값(매출 같은)이 아니라서 넣지 않았습니다. 대신 최신값, 기간 변화율, 표준편차를 넣었습니다.

## 2. FastAPI를 라우터/서비스로 나눈 기준

**한 문장**: 라우터는 "주소와 입출력"만, 서비스는 "규칙과 계산"만, 저장소는 "어디에 저장하나"만 맡깁니다.

- `routers/`: `POST /api/data` 같은 경로를 받아 서비스 함수를 부르고 결과를 돌려줌
- `services/`: 같은 날짜 중복 금지(409), 요약 계산, 프롬프트 만들기, GPT 호출, 도구 실행
- `repositories/`: Firestore 저장소와 테스트용 메모리 저장소. 같은 인터페이스라 갈아 끼울 수 있음
- 장점: `/api/chat`이 HTTP로 자기 자신을 부르지 않고 `DataService.summary()`를 바로 써서 빠르고 단순합니다. 테스트에서 저장소만 메모리로 바꾸면 키 없이 같은 코드를 검사할 수 있습니다 (pytest 70개).

## 3. Pydantic 입력 검증을 쓴 이유와 방식

**한 문장**: 잘못된 값이 DB와 AI까지 들어가기 전에, 요청 모양을 클래스로 정해 FastAPI가 자동으로 막게 했습니다.

- 위치: `app/schemas/`
- `DataCreate`: 날짜는 `date` 형식(YYYY-MM-DD), 1900년 이후, 한국 시간 기준 오늘까지(미래 금지) / 값은 0보다 크고 1,000만 이하인 숫자, `true`나 `"1334"` 같은 문자는 숫자로 바꾸지 않고 거절, 무한대·NaN 금지 / 메모 200자, 보이지 않는 제어 문자 제거
- `DataUpdate`: 바꿀 항목만 보내되 하나도 없으면 오류
- `ChatRequest`: 질문 1~1000자, 대화 ID는 영문·숫자·`-`·`_`만 (경로 조작 방지)
- 실패하면 422와 함께 "입력값을 확인하세요: value (...)" 같은 한국어 메시지를 돌려줍니다 (`app/factory.py`).

## 4. Firestore 저장과 CRUD

**한 문장**: `data` 컬렉션에 하루 한 문서, `conversations` 컬렉션에 대화 한 문서(그 안에 messages 배열)로 저장하고 Admin SDK로 읽고 씁니다.

- 연결: `app/database.py`가 환경 변수의 서비스 계정 키로 `firebase_admin.initialize_app` → `firestore.client()`
- CRUD: `collection.document().set()`(추가, 자동 ID), `stream()`(목록), `update()`(수정), `delete()`(삭제), 초기 251개는 `batch`로 한 번에
- 초기 데이터 자동 업로드: 서버가 켜질 때 `data` 컬렉션이 완전히 비어 있으면 CSV 251개를 한 번 올립니다 (`SEED_IF_EMPTY=true`, `app/services/seed.py`). 문서가 하나라도 있으면 건드리지 않아서 화면에서 고친 값이 덮어써지지 않습니다
- 읽기 횟수 절약: 전체 목록을 60초 동안 메모리에 들고 있고, 추가·수정·삭제 때 바로 비웁니다. 여러 요청이 동시에 와도 Firestore 전체 읽기는 한 번만 합니다 (무료 한도: 하루 읽기 5만 건)
- 같은 날짜 중복 확인: 캐시가 아니라 Firestore에서 그 날짜 문서만 찾아보고(`find_documents`), 확인과 저장을 잠금 안에서 한 번에 해서 동시에 눌러도 두 개가 생기지 않습니다
- 대화 불러오기는 (A) 방식: 목록 API는 messages를 빼서 가볍게, 상세 API에서 전체 메시지를 줍니다.

## 5. 컨텍스트 주입의 원리

**한 문장**: GPT는 내 데이터를 모르니, 질문할 때마다 요약을 글로 바꿔 시스템 프롬프트의 [사용자 데이터 요약] 칸에 넣어 함께 보냅니다.

- 흐름 (`app/services/chat_service.py`): ① 요약 조회 → ② `build_system_prompt`로 요약 삽입 → ③ GPT 호출 → ④ conversations에 저장
- 시스템 프롬프트에는 답변 규칙도 넣었습니다: 요약·도구 결과의 숫자만 쓰기, 데이터 마지막 날짜 기준으로 "이번 달" 해석, 원인 단정 금지, 투자 권유 금지
- 요약에 없는 값은 도구(function calling)로 더 읽습니다 ([TOOL_CALLING.md](TOOL_CALLING.md))
- 확인 방법: 테스트 `test_chat_injects_summary_and_saves`가 GPT로 보낸 메시지에 기간·개수·최고값이 들어갔는지 검사합니다.

**예상 질문**: 데이터를 바꾸면 AI 답도 바뀌나요?
→ 네. 요약을 질문마다 다시 만들고, 데이터가 바뀌면 캐시를 바로 비우므로 다음 질문부터 반영됩니다.

## 6. 배포에서 CORS, 환경 변수, 키 관리가 필요한 이유

**한 문장**: 프론트(Vercel)와 백엔드(Render)가 서로 다른 주소라 허락한 주소만 부를 수 있게 하고(CORS), 키는 코드가 아닌 서버 설정에만 두어 GitHub에 새지 않게 합니다.

- CORS: 브라우저는 다른 주소의 API를 부르기 전에 "이 주소에서 불러도 되나"를 서버에 묻습니다. `ALLOWED_ORIGINS`에 적힌 주소(운영 Vercel 주소, 로컬 주소)만 허락합니다. 넓은 정규식은 다른 사람의 Vercel 주소까지 허락할 수 있어 기본값에서 뺐습니다. CORS는 브라우저 규칙이라 로그인 같은 접근 제한은 아니라는 점도 알고 있어야 합니다.
- 환경 변수: 같은 코드를 로컬(`.env`)과 Render(대시보드 설정)에서 다른 값으로 실행하기 위해 씁니다. 프론트는 빌드 때 `API_BASE_URL`로 `config.js`를 만듭니다 (바닐라 HTML은 브라우저에서 환경 변수를 읽을 수 없어서).
- 키 관리: OpenAI 키와 서비스 계정 키는 Render 환경 변수에만 넣고, `.gitignore`로 `.env`와 키 파일을 막았습니다. 키가 브라우저로 가지 않도록 GPT 호출은 서버에서만 합니다.
- 비용 보호: 답변 700토큰 제한, 도구 왕복 최대 3번, 질문 1번 75초 상한, IP당 분당 10회·하루 100회, 서버 전체 분당 30회·하루 300회. IP는 헤더로 판단해 바꿔 피할 수 있어서, 진짜 비용 상한은 서버 전체 제한입니다. 실제 사용량은 `/api/chat` 응답의 `usage`(입력·출력 토큰 수)로 확인합니다.
