# 기능·비기능 요구사항 정의서

## 1. 프로젝트 개요
- 프로젝트명: AI Promise
- 목적: 기업이 정기공시에서 밝힌 AI 계획과 후속 실행 근거를 연결해 취업·이직 준비자가 기업의 AI 전략을 빠르게 확인하도록 돕는다.
- 핵심 사용자: 취업·이직 준비자
- 핵심 데이터: DART 정기공시
- 핵심 AI 기술: RAG + LLM/Agent-style workflow

## 2. 기능 요구사항

| ID | 기능명 | 요구사항 | 우선순위 |
|---|---|---|---|
| FR-01 | 기업 선택 | 사용자가 분석할 기업을 선택할 수 있어야 한다 | Must |
| FR-02 | AI 약속 추출 | 2024 사업보고서에서 AI 관련 미래 계획 문장을 추출해야 한다 | Must |
| FR-03 | 구체성 분류 | 약속을 구체적/방향성으로 분리해야 한다 | Must |
| FR-04 | 후속 공시 검색 | 2025 사업보고서와 2026 반기보고서에서 관련 근거를 검색해야 한다 | Must |
| FR-05 | 판정 | 근거 확인/일부 확인/공시에서 확인 불가/회사 미추진 공시 중 하나로 판정해야 한다 | Must |
| FR-06 | 원문 근거 표시 | 약속과 근거 원문, 보고서 위치, DART 링크를 보여줘야 한다 | Must |
| FR-07 | 인용 검증 | 근거 문장이 수집 원문에 실제 존재하는지 검사해야 한다 | Must |
| FR-08 | 면접 카드 | 검증된 결과를 바탕으로 면접용 핵심 이슈·답변 소재·역질문을 제공해야 한다 | Must |
| FR-09 | AI 고지 | AI가 생성한 분석임을 화면에 표시해야 한다 | Must |
| FR-10 | 사용자 피드백 | 실제 사용자의 피드백을 수집할 수 있어야 한다 | Must |

## 3. 비기능 요구사항

| ID | 항목 | 요구사항 |
|---|---|---|
| NFR-01 | 근거성 | 실행 관련 사실은 공시 근거와 연결되어야 한다 |
| NFR-02 | 인용 무결성 | 근거 인용은 exact-match 검증을 통과해야 한다 |
| NFR-03 | 표현 안전성 | '거짓', 'AI 워싱'처럼 단정적인 표현을 사용하지 않는다 |
| NFR-04 | 개인정보 | 사용자 테스트에서 이름·전화번호·이메일을 저장하지 않는다 |
| NFR-05 | 재현성 | 판정기준 버전과 LLM 실행 로그를 남긴다 |
| NFR-06 | 모바일 | 320~390px 화면에서 주요 기능이 깨지지 않아야 한다 |
| NFR-07 | 배포 | 외부에서 접근 가능한 URL로 제공되어야 한다 |

## 4. 필수 기술 요소 대응
- **RAG**: 후속 정기공시에서 약속과 관련된 근거 문단을 검색해 LLM 판정에 제공
- **AI Agent / Agent-style workflow**: 약속 추출 → 검색 → 근거 평가 → 필요 시 재검색 → 판정 → citation verification → 면접 카드 생성
- **자동화 파이프라인(보조)**: DART PDF 입력부터 화면용 JSON 출력까지 Python pipeline으로 연결
