# 3분 시연 대본

> 사용자 수와 점수는 고치기 전 화면을 본 응답 12명 기준입니다(10/19 23:58까지). 고친 화면이 배포된 뒤 설문 2명이 더 응답해 설문은 모두 14명입니다 (README 9장).
> 삼성전자 화면은 사람이 원문을 읽고 판정한 검증용 시연 데이터(PR #19, 사람 원문 검토 완료)라서 0:40 부분의 괄호 문장을 꼭 넣습니다. 10/19 기준 삼성전자 화면에는 '공시에서 확인 불가' 판정이 없어서, 판정 종류를 하나씩 말하지 않습니다.

## 0:00–0:20 문제
“취업을 준비하면서 기업의 AI 전략을 제대로 보려면 사업보고서를 여러 연도에 걸쳐 직접 비교해야 합니다. 문제는 한 보고서가 수백 쪽이고, 과거에 무엇을 계획했는지와 이후 실제 공시 근거를 연결하는 데 시간이 많이 든다는 점입니다.”

## 0:20–0:40 서비스
“AI Promise는 이 과정을 자동화합니다. 과거 사업보고서에서 AI 관련 약속을 찾고, 후속 공시에서 실행 근거를 검색한 뒤 원문과 함께 판정해 보여줍니다.”

## 0:40–1:45 실제 화면
“첫 화면에서 회사를 검색합니다. 분석을 마친 회사는 바로 결과가 열리고, 아직 분석하지 않은 상장 기업은 '아직 분석 전'으로 그대로 보여 줍니다. 삼성전자를 보겠습니다.”

(꼭 넣기) “지금 보시는 판정은 사람이 공시 원문을 직접 읽고 판정한 검증용 데이터입니다. 첫 화면의 확장 분석 기업 3곳은 AI 엔진이 공시를 자동으로 받아 같은 4단계 형식으로 만든 결과입니다.”

“약속 목록에는 약속마다 판정이 붙어 있고, 판정별 개수만 보여 줍니다. 점수나 순위는 만들지 않았습니다.”

“약속 하나를 누르면 약속, 후속 공시의 근거, 판정이 시간 순서로 이어집니다. 근거 문장이 원문에 글자 그대로 있는지는 코드가 확인한 '원문 존재 확인'으로, 판정을 사람이 원문을 읽고 확인했는지는 '사람 원문 검토'로 따로 보여 줍니다. 단계별 설명은 접어 두어 핵심만 먼저 보입니다.”

“여기서 중요한 건 AI가 결론만 주는 것이 아니라 사용자가 DART 원문으로 다시 확인할 수 있다는 점입니다.”

“마지막 면접 카드는 공시에서 확인할 핵심 이슈, 면접에서 활용할 소재, 회사에 물어볼 역질문 세 묶음입니다. 완성 답변이 아니라 공시 근거가 붙은 소재로만 제공합니다.”

(시간이 되면) “면접 카드 아래에서 지원 직무를 고르고 이력서 내용을 넣으면, 제 경험을 지원 직무 역량을 거쳐 이 회사 AI 약속에 연결합니다. 직접 다룬 경험과 직무 역량으로 옮겨 쓸 수 있는 경험을 나누고, 이어지지 않는 경험은 억지로 연결하지 않고 '면접 전에 준비할 것'으로 돌립니다. 이력서 인용은 제가 넣은 글에 그대로 있는 구절만 보여 주고, 이력서는 저장하지 않습니다.”

## 1:45–2:15 AI Native 구조
“기술적으로는 RAG로 후속 공시에서 관련 문단을 검색하고, LLM이 그 문단만 근거로 판정합니다. 판정이 '공시에서 확인 불가'이면 새 검색어로 다시 찾고(처음 포함 최대 3번), 마지막으로 선택된 인용문이 실제 수집 원문에 있는지 원문 존재 확인(citation verification)으로 다시 검사합니다.”

“전체 흐름은 OpenDART 자동 수집부터 Collect, Extract, Retrieve, Judge, Verify, Interview Card, Export까지 Python 자동화 워크플로우로 연결했습니다.”

## 2:15–2:40 사용자 테스트
“실제 사용자 12명을 대상으로 테스트했고, 이해도 평균 4.50/5, 신뢰도 4.58/5, 면접 활용 의향 4.67/5를 기록했습니다. 고친 화면을 배포한 뒤 2명이 더 응답했습니다.”

“반복적으로 나온 피드백은 화면을 이해하기 어렵다는 것이었고, 이를 첫 화면 사용 순서 안내, 약속·근거 형광 표시, 용어 풀이, '실행 시기 전' 표시, 이력서 분석 진행 표시로 수정해 GitHub PR #41에 반영했습니다. 고친 뒤에는 글자가 많다는 의견과 이력서 연결이 직무보다 제품 약속에 끌려간다는 의견을 받아, 설명을 접어 두고 지원 직무 기준으로 연결하도록 한 번 더 고쳤습니다.”

## 2:40–3:00 한계와 결론
“AI Promise는 기업이 실제로 약속을 지켰는지를 단정하지 않습니다. 공시에 없는 실행은 알 수 없기 때문에 근거를 못 찾은 경우 ‘공시에서 확인 불가’라고 표시합니다.”

“저희가 만든 것은 기업을 대신 평가하는 AI가 아니라, 사람이 공식 공시를 더 빠르고 검증 가능하게 읽도록 돕는 AI 조사 도구입니다.”
